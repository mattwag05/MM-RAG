# Retrieval evaluation (Phase 6)

Deterministic scoring of `search` against gold source citations. No LLM judging:
MM-RAG is evidence-first (`synthesize=false` everywhere), so retrieval quality is
measured by whether the cited gold source appears in the returned hits.
LLM-judged metrics (RAGAS faithfulness / answer relevance) are deliberately out
of scope until synthesis becomes an actually-used path.

## Running

```bash
make eval        # smoke set: ingests tests/fixtures/speech.mp4, scores 3 questions
make eval-full   # full set: fetches public URLs via yt-dlp (slow, local only)
```

Or directly, against whatever store `MMRAG_DATA_DIR` points at:

```bash
uv run --extra dev --extra m3-visual mmrag eval --dataset eval/smoke.jsonl \
  --mode hybrid --top-k 10 --json report.json --fail-under-recall 0.8
uv run --extra dev --extra m3-visual mmrag eval --sweep top_k=3,5,10
```

Note: the smoke media fixture is generated by the test suite — run `make test`
once first (needs `ffmpeg` plus a TTS tool, `say` on macOS). Media is never
committed; datasets reference re-fetchable URLs or local fixture paths only.

## Dataset schema (JSONL; `#` lines are comments)

```json
{
  "id": "lec01-q03",
  "question": "What loss function does the lecture derive?",
  "media": [{"source": "https://...", "kind": "url"}],
  "gold": [{"source": "https://...", "time_range": [812.0, 905.0]}],
  "tags": ["lecture", "transcript"]
}
```

- `media` — sources ingested when `--ingest` is passed (skipped otherwise).
- `gold` — sources that answer the question. Matched by suffix against
  `assets.source_url` / `assets.mezzanine_path`, so full URLs and fixture
  basenames both work. `time_range` is optional; when present a hit must
  overlap it to count.
- Unresolved gold (source not ingested) logs a warning and scores 0 — check the
  `gold unresolved` row before trusting a low recall number.

## Metrics

| Metric | Definition | Target |
|---|---|---|
| recall@k | any gold source in the top-k hits (mean over questions) | high |
| context precision@k | gold-relevant hits / hits returned (mean) | ≥0.80 |
| MRR | 1/rank of first gold-relevant hit | high |
| latency p95 | `perf_counter` around `handle_search`, after one warm-up | <200 ms |
| ingest media-hr/min | `sum(duration_s)` / wall minutes (`--ingest` only) | ≥1 |

`first-hit streams` shows which retrieval stream (fts, vector, content_items,
graph) produced the first gold hit per question — a free diagnostic on which
RRF stream is earning its keep.
